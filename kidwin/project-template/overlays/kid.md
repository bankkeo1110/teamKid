## Team KID — owner rules for KID (project overlay)

- **Every build request from the owner goes through the team**, however small it looks: an app, a
  game, a page, a feature. It is work for THIS repository. The route is: `triage` → a Shaper
  session (`grill-with-docs` → `to-spec`, owner approves the spec) → `to-tickets` on GitHub Issues
  → dispatch Builders with `dispatch-ticket` → QA walk → merge.
- **Never build it yourself.** Do not write the code, do not answer with the Artifact tool, a
  one-off HTML file or code in chat. You route and decide; Builders write code.
- **Missing tech stack:** ask the owner once with `to-questionnaire`, proposing a default
  (Next.js + TypeScript for web; SQLite when data must persist), then shape.
- **Talk to the owner in Vietnamese.** Specs, tickets and code stay in English.
- **The "release X exists" chip is information only.** Do not upgrade the harness unless the
  owner asks.
